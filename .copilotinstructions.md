# Copilot Instructions for uFawkes.dev

## Repo Purpose
uFawkes.dev is the public website for the uFawkes open-source platform engineering ecosystem.

This repo:
- is a Jekyll site served from the repository root on the `main` branch
- uses `minima` as the theme and custom include/layout overrides
- contains product/marketing pages, learn pages, and blog posts

## Tech Stack and Commands
- Runtime/build: Jekyll (Ruby)
- Theme: minima
- Plugins: jekyll-feed

Primary commands:
- `make serve` -> local development server
- `make build` -> production build
- `bundle exec jekyll serve` and `bundle exec jekyll build` are equivalent direct commands

When making changes, prefer validating with `make build` if the environment supports Ruby gems.

## Source of Truth Structure
- Global config: `_config.yml`
- Main nav data: `_data/navigation.yml`
- Shared header/nav and JS behavior: `_includes/header.html`
- Shared stack page layout: `_layouts/stack.html`
- Site styles: `assets/css/main.css`
- Home page: `index.md`
- Blog listing: `blog/index.md`
- Blog posts: `_posts/YYYY-MM-DD-title.md`
- Learn and stack pages: folder `index.md` files (for example `learn/index.md`, `obs/index.md`)

## Editing Rules
1. Preserve front matter and required page fields.
2. Keep URLs and permalinks stable unless the task explicitly asks for URL changes.
3. Use Jekyll/Liquid-safe patterns and avoid introducing unsupported templating.
4. Maintain existing tone: practical, implementation-focused, DORA/platform engineering language.
5. Keep changes minimal and targeted; do not rewrite unrelated content.

## Front Matter Conventions
For general pages, include at minimum:
- `layout`
- `title`

For blog posts in `_posts/`:
- filename must be `YYYY-MM-DD-slug.md`
- keep `layout: post`
- include `title`, `date`, and `permalink`
- prefer concise `excerpt`
- keep category tags aligned with existing style

For stack pages using `_layouts/stack.html`, preserve required keys used by the layout:
- `stack_name`
- `hero`
- `summary` (when present)
- `coming_soon`
- `repo_url` and `repo_name` (for live stacks)
- `notify_title` and `notify_copy` (for coming-soon stacks)
- `screenshot_placeholder`
- `features`
- `quick_start`
- `compose_with`

Do not remove fields referenced in the stack layout unless you also update the layout safely.

## Links, Liquid, and Navigation
- Prefer `relative_url` for internal links in templates/includes.
- Use leading-slash canonical paths for internal destinations (for example `/learn/`).
- External links opened in new tabs should include `rel="noopener noreferrer"`.
- If navigation structure changes, update `_data/navigation.yml` and verify header behavior still works.

## CSS and UI Guidance
- Primary stylesheet is `assets/css/main.css`; keep selectors consistent with existing naming.
- Preserve responsive behavior at current breakpoints (`767px` and `640px`) unless asked to redesign.
- Keep visual language consistent with the existing site: clean, readable, and content-first.
- Avoid adding heavy JS frameworks or build systems.

## Accessibility and Content Quality
- Keep semantic heading order logical (`h1` -> `h2` -> `h3`).
- Ensure images/iframes have meaningful `alt`/`title` attributes.
- Maintain keyboard-friendly interactions for nav and controls.
- Keep copy concise, specific, and free of hype.

## Safety Checks Before Finishing
When possible, verify:
1. `make build` succeeds.
2. No broken Liquid syntax.
3. Internal links and permalink targets still resolve.
4. Updated pages render without obvious layout regressions on mobile and desktop.

## Do Not
- Do not commit secrets or environment-specific credentials.
- Do not add unrelated dependencies.
- Do not change deployment assumptions (GitHub Pages from `main` root) unless explicitly asked.
- Do not remove existing includes/layout behavior without replacing equivalent functionality.
